# C01 portable contract draft evidence

Date: 2026-10-20. C01 is **done** as the reviewed schema-v1 target. The Swift and Kotlin adapters

## Draft and fixtures

`Contracts/v1/` contains a draft manifest description, a JSON Schema draft 2020-12 file, and 13
input/expected pairs: minimal legacy record, full record, nested unknown members, unknown format,
unknown role, deletion/equal timestamp, mixed-case UUID, malformed hash, unsafe filename, invalid
number, out-of-range progress, unsupported version, and numeric overflow. The adoption map names
the later Swift and Kotlin tasks that must consume these same files.

Validation performed on 2026-10-20:

- Parsed all 27 JSON files with Python's standard JSON parser.
- Confirmed all 13 inputs have exactly one matching `.expected.json` file, with no unmatched files.
- Added a repeatable local validator with `jsonschema==4.25.1` pinned in
  `scripts/contract-validation-requirements.txt`; it uses `uv run` and does not
  install a global tool. Exact command:
  `uv run --with-requirements scripts/contract-validation-requirements.txt python scripts/validate-contract-v1.py`
- Tool versions for that run: `uv 0.11.15`, Python `3.11.15` (uv-managed),
  `jsonschema 4.25.1`.
- Validator result: schema passes Draft 2020-12 meta-schema validation; all 13
  fixture inputs match their expected schema disposition (7 valid, 6 invalid).
  In particular, `unsafe-filename.json` is structurally valid because filename
  safety is an adapter policy check outside JSON Schema, and
  `numeric-overflow.json` is rejected against the finite binary64 timestamp
  bound.
- `git diff --check` passed for the contract validation changes.

The fixtures are not yet wired into Swift or Kotlin tests. Integrator review
confirmed the contract constraints as the v1 target: absent legacy fields remain
permitted where documented, bounded numeric and unsafe path expectations are
explicit, unknown extensible members must round-trip, current platform gaps are
characterized, and merge policy remains in C02. Adapter conformance remains
with S01/K01.

## Reviewed compatibility boundaries

- `unsafe-filename.json` is schema-valid and must be rejected by adapter path-safety checks; JSON
  Schema intentionally does not encode platform filesystem policy.
- `unknown-role.json` records Android's current arbitrary-string behavior and Apple's current
  closed-role limitation. Future adapters must preserve opaque data without inventing a role.
- The expected JSON files are reviewed semantic notes, not executable assertions about current
  platform behavior; S01/K01 must add those assertions and durable round-trip coverage.
- `deletion-equal-time.json` characterizes parsing only. Deterministic merge policy remains in C02.
