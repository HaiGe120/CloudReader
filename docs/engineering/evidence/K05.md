# K05 Android library mutation durability evidence

## Scope

K05 hardens Android library mutations against stale snapshots and interrupted file operations. The changes are limited to the Room DAO mutation/transaction APIs, `LibraryRepository`, and focused mutation durability instrumentation tests. Room schema v1, its table/column definitions, and repository-facing UI behavior remain unchanged outside the targeted mutation cases.

The repository now applies favorite/progress/opened changes as field-specific updates; demo seeding checks deletion state transactionally; deletion commits a tombstone before managed-file removal; retry can finish removal after file-operation failure; and sync installation stages and verifies the file move before committing after an atomic freshness/tombstone recheck. Tombstone timestamp advancement carries forward opaque JSON. The `installSyncedBook` Boolean is safe for the current `SyncEngine`: a false result means the repository found a newer/equal local row or an equal/newer tombstone at commit time, and the subsequent snapshot retains that local winner / deletion state. This assumes the existing snapshot-based publication path remains in use.

## Focused acceptance coverage

`LibraryMutationDurabilityTest` verifies concurrent stale-snapshot favorite/progress writes, demo deletion surviving repository recreation, failed install rename leaving no row or staged file, interrupted deletion preserving a durable tombstone and retrying successfully, and remote install rechecking latest local state while preserving reader location. The interrupted-delete test also checks that an existing tombstone's opaque JSON survives timestamp advancement.
