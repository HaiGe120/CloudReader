# D01 Compose Desktop feasibility record (prototype)

Date: 2026-10-24

`Apps/Desktop` contains a bounded Kotlin/JVM Compose Desktop prototype. The chosen stack is Compose Multiplatform Desktop with a JVM 17 toolchain, keeping Windows and Linux UI in one source set while leaving native integrations behind interfaces.

Verified by source inspection in this checkout:

- The application entry point creates a durable local repository under the user profile and opens a Compose window.
- A TXT import copies source bytes into private app storage and persists a text offset; reopening the repository restores that offset.
- PDF and EPUB imports are reported as unsupported. No AndroidX PDF or Android Readium dependency is introduced.
- `CredentialStore` is secure by default. The entry point reports secure credential storage as unavailable until Windows Credential Manager and Linux Secret Service adapters are added; a separately named plaintext adapter requires explicit user opt-in and applies user-only file permissions where supported.
- `FilePicker`, `DropTarget`, `LibraryRepository`, and `ContentReader` define the adapter seams for the following slices.

The shared Kotlin core tests pass locally with JDK 17. Desktop Gradle tests and
packaging remain CI-only on this host because the Compose Desktop plugin is not
cached; no Windows/Linux runtime or accessibility claim is made from the Mac
checkout.

The actual Windows/Linux build, screen-reader behavior, package size/startup, native credential services, and PDF/EPUB engine evaluation remain open D01 evidence. A Mac-hosted build must not be used as proof for those operating-system checks.
