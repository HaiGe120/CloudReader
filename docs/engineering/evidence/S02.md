## Behavior and acceptance cases

`CloudSyncCoordinator` retains destination selection, foreground coalescing, progress messages, two-pass multi-destination propagation and per-destination outcomes. It now injects a store factory, clock, scheduler and connection check for deterministic coordination tests. `AppleSyncPipeline` receives the `AppleSyncRepository` port (with `BookLibrary` retaining its facade conformance) and remote store factory, and owns one destination's read/validate/merge/transfer/publish pass. Existing hash preflight, missing-copy recovery, read/upload rechecks, tombstone handling and provider cleanup are retained. SFTP resource cleanup remains delegated through the injected closer.

The new fake-store cases cover missing/corrupt remote bytes, missing local-copy restoration without overwriting progress, local progress and deletion during suspended downloads, latest progress publication after a suspended upload, manifest failure/retry, zero book-object uploads for an empty library, and one failed destination alongside a successful destination. All test libraries/preferences use UUID-scoped temporary storage and suites.
