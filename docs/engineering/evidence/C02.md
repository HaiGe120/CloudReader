Date: 2026-10-20. C02 contract design and paired S03/K02 policy adoption/conformance review are **done at local gates**. Apple and Android tests now construct merge cases from shared vector inputs and assert the expected semantic outcomes. Live provider and cross-device validation remain open. ## Reviewed policy

`Contracts/v1/merge-vectors.json` contains 12 semantic vectors. The policy specifies deletion-wins-on-equal-time with the greatest tombstone retained; IEEE-754 binary64 timestamp comparison; portable equal-time tie-breaking using RFC 8785/JCS; message-ID union and ordering; explicit recovery for conflicting book/message/opaque candidates; replay/provider-order invariance; and the limits imposed by wall-clock skew and unconditional manifest writes.

The vectors are abstract semantic cases, not schema-valid manifests. Adapter tests must substitute valid UUIDs and create valid v1 inputs. Recovery candidates are a local durable target for S03/K02. The current v1 manifest has no defined encoding for transporting multiple candidates, so cross-device recovery requires a reviewed protocol extension. The policy makes no transactional multi-writer claim and no production merge behavior changed in C02.

The compatibility audit that informed the vectors is summarized in the contract's “Current code” section: current tie behavior is order/local-biased, same-ID message payload collisions can silently lose a candidate, Android and Apple unknown-field handling differ, and two-pass provider propagation does not prevent lost concurrent writes.
