# S03 — Apple sync merge-policy adoption

Status: implementation, local verification, and paired shared-vector conformance review complete with K02. Both platform suites now construct merge scenarios from shared vector inputs and assert shared expected values.

## Owned paths and behavior

- `Apps/Shared/AppleSyncPipeline.swift` now builds local metadata/content-hash snapshots and applies `RemoteLibraryManifest.merging(_:)` for provider and local state. It applies merged conversations and max tombstones, preserving deletion-wins at equal timestamps.
- The pipeline persists recovery candidates and root opaque manifest fields through `AppleSyncLocalStateStore`. Root unknown fields are unioned across provider runs and app restarts; conflicts stay in the app-private journal and do not add v1 wire keys.
- Remote manifest preflight remains before library mutation. Selected remote book objects are still required and SHA-256 checked before installation. A deletion is rechecked after a suspended download. Local content is resnapshotted after upload; up to three upload/resnapshot rounds ensure a published local SHA has been uploaded. If content keeps changing, sync fails before manifest publication.
- The merged local sync snapshot must persist successfully before the canonical v1 manifest is published. Provider cleanup remains awaited on success and error.
- `Apps/iOS/CloudReaderTests/AppleSyncPipelineTests.swift` uses temporary libraries, isolated preferences, fake providers, and per-test local sync-state directories. It covers canonical equal-time book selection and durable alternatives, exact v1 top-level wire keys, root unknown-field union across provider calls/restart, deletion equality/replay, provider order/retry semantics, a byte edit during upload, local deletion during download, failed local snapshot persistence, corrupt/missing objects, and manifest retry.

## Limits

- V1 manifest writes remain unconditional. Sequential provider passes and these tests do not make concurrent writers transactional; concurrent devices can overwrite unseen changes.
- Recovery candidates are durable on this device only. V1 has no reviewed wire representation for transporting alternatives to another device.
- The bounded upload/resnapshot loop retries three times; continued content changes leave the provider manifest unchanged and require a later sync.
- No live provider, cross-device round trip, or device test was run. The focused iOS simulator run covers `AppleSyncPipelineTests`; it does not run the full Apple test suites.
