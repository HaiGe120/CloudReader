# A05 — Shared scalar reader pagination

## Scope delivered

- Added Foundation-only `ReaderPageLayout`, `ReaderTheme`, `ReaderFont`, and `ReaderPaginationPolicy` to `CloudReaderCore`. Existing preference raw values remain unchanged.
- iOS and macOS now use the same measured-page boundary selection and page/spread progress calculations. UIFont/NSFont measurement and paragraph styling remain in each native app.
- macOS reader font/theme/layout preferences now resolve through the shared typed values. Existing stored strings and fallback choices are preserved.
- Added Core tests for the appearance raw-value matrix, paged progress boundaries including 15/22 and 1/49 page counts, Unicode pagination, native-measurement injection, and cancellation.

## Checks

- `swift test --package-path Packages/CloudReaderKit --build-path <local path>` — passed **26/26, 0 failures**.
- Full iOS simulator suite — passed **85/85, 0 failures** at `<local path>`.
- Full macOS suite — passed **2/2, 0 failures** at `<local path>`.
- `git diff --check` passed after integration. Initial Apple compile attempts exposed missing direct imports for the newly shared Core types in two test files and missing explicit returns in both native adapters; those integration defects were fixed before the passing full runs.
- The canonical generated projects include the shared source set; pagination measurement stays native to UIFont/NSFont.

## Limits

No live/device reader interaction was performed. Native measured-fit behavior is covered by the existing iOS UI test and should be included in the coordinator's Apple test run.
