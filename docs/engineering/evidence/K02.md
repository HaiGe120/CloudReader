# K02 evidence — Android reviewed merge policy

Status: implementation, local Android verification, and paired shared-vector conformance review complete with S03. The Android test constructs policy cases from the shared inputs and validates the shared expected results, including all provider orders, replay, retry, and documented clock-skew limits.

Baseline: shared checkout contained active Android, Apple, contract, and documentation work. This task preserved that work. The Android merge-policy implementation is isolated to the pure sync policy/codec/engine paths plus the narrow, coordinator-approved K05 repository/DAO commit seam. No contract, schema/version, Gradle, project, UI, or provider protocol changes were made.

The Android merge path now selects a newest book candidate and resolves equal-time ties by JCS canonical UTF-8 bytes of portable `{book, sha256}` values, excluding unknown fields and device-local data from the tie key. Complete distinct book candidates remain in an atomic app-private recovery journal at `files/CloudReader/sync-recovery-v1.json`; entries are deduplicated and sorted across retries. Conversation metadata ties use a canonical portable record; messages union by canonical UUID, choose the canonical first complete payload for collisions, and sort by creation time then UUID. Tombstones retain the greatest timestamp and suppress equal-time records. Opaque values merge as whole JSON values, union disjoint fields, choose canonical-first for conflicts, and preserve conflict alternatives in local recovery with entity identity. Root-level opaque fields are unioned across destinations using a separate atomic app-private snapshot at `files/CloudReader/sync-opaque-v1.json`, then included in outgoing v1 manifests. The remote v1 manifest shape remains unchanged.

Equal-time content replacement uses an opt-in repository path only when sync selected a different-hash JCS winner. It captures the exact current `BookRow`, stages and verifies the downloaded bytes, then commits only if that exact row is still current and no tombstone suppresses it. If the JCS winner changes portable metadata while the hash is unchanged, sync commits those fields against the exact captured row without rewriting book bytes; it preserves the Android managed filename and local reader location. Existing callers keep strict-newer behavior. A local row/file survives a failed or stale commit.

Focused deterministic tests cover the shared 12-vector file, deletion equality, book/chat/message tie permutations, duplicate/repeated merges, opaque unknown fields across destinations and store recreation, canonical UTF-8 ordering, JCS exponent thresholds, and recovery journal replacement/deduplication. Instrumentation cases cover equal-time replacement, rejection after a local row changes during staging, failed replacement retaining the old file/row, and metadata-only updates preserving the managed file and device-local location.
