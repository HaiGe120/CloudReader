# K06.settings — Android settings state and actions

Status: complete. Coordinator reviewed the state extraction and confirmed the Android unit/lint/build gates passed.

## Scope

Added a lifecycle-aware `SettingsViewModel` with immutable `SettingsUiState`, focused setting actions, and an injectable `SettingsStore`. The Compose screen observes that state and delegates field edits, provider selection, and persistence to the ViewModel. The existing screen text, control order, styles, provider IDs, preference/vault keys, defaults, validation, and selection-trigger behavior are preserved. `AssistantScreen` behavior and app-root wiring were not changed.

Changed paths: `Apps/Android/app/src/main/kotlin/io/github/haige120/cloudreader/AssistantSettingsScreen.kt`, new `SettingsViewModel.kt`, new `SettingsViewModelTest.kt`, and this evidence file.

## Acceptance evidence

- Settings load the existing AI profile and SFTP port, keep the `My AI`, `openAIResponses`, port `22`, and `CloudReader` defaults, and reflect provider-selection flow updates.
- WebDAV and SFTP save their existing secure/preference keys, trim URL/directory/key values as before, and select their provider through the existing preference flow.
- Invalid non-HTTPS WebDAV/AI endpoints report the same validation messages without selecting/saving; blank AI keys preserve the previously stored key.
- Successful WebDAV, SFTP, and AI saves clear their password/key form fields as before.
