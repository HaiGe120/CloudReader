# CloudReader 1.2.0 — Android, Windows and Linux preview

Date: **2026-10-31** · Tag: **`v1.2.0-unified-preview`** · **Prerelease**

This release brings the Android, Windows and Linux applications together around
shared Kotlin/Compose UI and portable services, using the enabled iOS readers as
the feature reference. It is not complete iOS parity or production acceptance.
The existing native iOS/macOS apps and their releases are unchanged.

## Downloads

The [GitHub release](https://github.com/HaiGe120/CloudReader/releases/tag/v1.2.0-unified-preview)
provides:

- `CloudReader-1.2.0-all-platforms-preview.zip`: all three apps, manifests,
  package checksums, UI/test evidence, this release's notes and the license companion.
- `CloudReader-1.2.0-android-debug.apk`: Android 12+ / API 31+, version code 4.
- `CloudReader-1.2.0-windows.msi`: Windows x64, unsigned, bundled Java runtime.
- `CloudReader-1.2.0-linux.deb`: Debian 12 amd64 baseline, bundled Java runtime.
- `CloudReader-1.2.0-third-party-notices.zip`: full retained notices, runtime
  licenses, upstream attributions and dependency metadata; keep it with redistributions.
- `SHA256SUMS`, `delivery.json`, the progress report and matching Java/OpenJFX source archives.

**Do not uninstall an existing Android app or clear its library to force an
update.** This APK is CI debug-signed and may not match the original signing key
or the certificate registered for Google authorization. In-place updates need
the original matching key. Neither this APK nor the unsigned MSI is a trusted
production distribution channel. Use disposable libraries for preview acceptance.

## What is included

| Area | Android | Windows / Linux |
| --- | --- | --- |
| Library | Shared responsive Compose UI; Room v1 | Same shared UI; durable, legacy-compatible local storage |
| Reading | TXT/PDF/Readium EPUB, shared FB2 preparation, bounded CBZ | WebKit TXT/EPUB/FB2, PDFBox PDF, bounded CBZ |
| Reader controls | Appearance, hide/show, selection and resume adapters | Appearance, keyboard/wheel input, selection, facing pages and resume |
| Assistant | Remote protocols, consent, history, cancel/retry | Shared transport/UI and durable conversations |
| Sync | Existing provider/Keystore adapters and portable v1 model | Folder, Google appDataFolder, Dropbox, pCloud, HTTPS WebDAV and pinned SFTP |
| Secrets | Android Keystore | Windows Credential Manager / Linux Secret Service; session-only when unavailable by default |

MOBI/AZW3/CBR remain storage-only on these three clients, matching the current iOS
gates. Apple Foundation Models, Siri and iCloud integration are not replicated.
Publisher styles/scripts are sanitized in desktop EPUB rather than reproduced
by a full-fidelity layout engine.

## Known gaps and risks

- Production/update signing and installed-OS installation/update/file-association,
  accessibility, scaling and graphics matrices remain open.
- Live OAuth/token refresh, OS vaults, live AI and Apple↔Android↔desktop sync need
  dedicated test accounts; personal credentials were not used for verification.
- Schema v1 uses unconditional manifests: simultaneous writers can overwrite
  unseen changes. Sync devices sequentially and keep backups. No compare-and-swap
  or automatic conflict choice is claimed.
- Desktop conversation sharing/export and broad library export, full iOS visual
  parity and physical Android gestures/lifecycle need further acceptance.
- Some transfers use bounded in-memory bytes and blocking I/O; no streaming or
  immediate-cancellation guarantee is claimed.
