# CloudReader 1.2.1 — Google connection and readability preview

**2026-11-01 · `v1.2.1-google-connect-preview` · Prerelease**

Simpler Google connection and readable light/dark settings on Android, Windows
and Linux. Native iOS/macOS are unchanged. Personal-account Google consent,
refresh and backup remain **unverified**; this is not a production-acceptance claim.

## Changes

- Normal Android connection is **Connect → choose an account → approve Drive
  backup access** using native Google Play services. Readers need no client ID,
  secret or Google Cloud project. Windows/Linux bundle the approved dedicated
  **Desktop app** client, verified from both actual packaged launchers.
- Custom credentials are optional under **Advanced Google settings**. Existing
  custom grants are preserved. **Use standard Google connection** retains saved
  advanced credentials, clears only the old Google grant and requires reconnecting;
  books and other provider connections are retained.
- Shared destination cards pair foreground/background colors in both themes;
  long descriptions/actions remain readable. Contrast tests cover 17 text pairs.
  Android root/system-bar colors and protocol chips follow the active theme.
- Failures retain sanitized diagnostics. `UNREGISTERED_ON_API_CONSOLE` offers
  registration help; generic error 8 alone is not treated as a certificate diagnosis.
  Failed desktop authorization does not falsely enable its destination.
- Both approved new Google registrations were verified in the existing project;
  older Android/Rclone clients, audience, branding and billing remain unchanged.
  The Drive API is enabled. Consent may still show the existing project's Rclone
  branding. No backups were migrated. No personal Google tokens were uploaded.

See [Google setup](../GOOGLE_DRIVE_SETUP.md) for reader and maintainer guidance.

## Remaining limits

- Personal-account Google sign-in, consent, token refresh and Drive backup/sync
  are **not verified** on any target. Registration, configuration fingerprints,
  UI tests and account pickers are not live OAuth acceptance.
- Android installed update/data retention, physical-device behavior, MSI/DEB
  installation/update, OS-vault acceptance and broad accessibility/display
  matrices remain open. Windows is unsigned; Android signing limits are above.
- Live AI/provider checks and Apple↔Android↔desktop round trips require isolated
  libraries and authorized test accounts. Schema v1 retains unconditional
  manifest writes and concurrent-writer overwrite risk; sync sequentially and
  keep backups.
- Reader scope remains TXT/PDF/EPUB/FB2/CBZ; MOBI/AZW3/CBR are storage-only here.
  This is not full iOS parity or desktop export/share acceptance. See the
  [previous convergence scope](1.2.0-unified-preview.md).

Native Apple code, schema v1, dependencies, SDK minimums, application IDs,
credential identifiers and imported originals are unchanged. Original application
source remains [MIT licensed](../../LICENSE); dependencies retain separate terms
in [third-party notices](../../THIRD_PARTY_NOTICES.md) and source companions.
